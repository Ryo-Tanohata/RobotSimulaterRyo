# ダッシュボードの設計: 「村の跡と記録」

書いたのは Claude (2026-10-09)。数はすべて、`sim/society/data/` の写し (28年30日目 = 3389 日目、G5、記録の季節 97) から計算した。資料からそのまま写した数はない。季節が進むと数は変わる (作るときに毎回計算しなおす)。

この世界の 1 年は 120 日 (30 日の季節が 4 つ。夏・秋・冬・春の順で、0 日目は夏)。本物の 1 年とはちがう。日付は「28年30日目」(= 3389 日目 ÷ 120 の商が年、余り + 1 が日目) と書く。この文書では、あとに通しの日 (3389 日目) をそえる。

## 1. 何を見せるか

### 1.1 本人が決めたこと (2026-10-09)

| 決めたこと | ダッシュボードでは |
|---|---|
| 1 行 = 1 季節 (日ごとの出来事は今のまま) | 行はいつも季節。「この世界の時計」で季節を選ぶ |
| 見る単位は史実にする | 物ごとの単位 (個・本・頭・匹・基・軒・m²・つかみ)。kcal は出さない |
| 出すのは村が残すものだけ。文字の前は考古学の証拠を今の言葉で。G6 からは村の記録 (印 → 数え札 → 封筒 → 粘土の板 → 文字) と今の言葉の説明 | G5 までは「掘ってわかる跡」だけ。G6 からは「記録」のタブに村の記録が出る |
| 気持ち・言葉・性格は出さない (アプリの欄に日付つきで残す) | 出さない。アプリの「履歴書」などへのリンクだけ置く |
| 年齢は区分 (乳飲み子 0〜2・子 3〜11・手伝える子 12〜14・大人 15〜54・年寄り 55〜) | 墓の年ごろは区分で出し、骨で言える限りの注をつける |
| 年の名前は村の人が決める (口で伝える年代記) | 「年の名」として、跡とは別の場所に出す |
| 人と家の番号 (P001・H01) は表に出さず、記録をつなぐために使う | 画面にも JSON にも出さない。考古学者の呼び方 (建物 1・墓 1・印 A) を使う |

### 1.2 おすすめの通りに決めたこと

本人の決め方 (「細かい決めごとは Claude がおすすめを選んで進め、何を決めたかを伝える」) にしたがって、次の問いはおすすめの答えにした。

考古学の問い (`docs/research/archaeological_evidence.md` 7.):

| 問い | 決めたこと |
|---|---|
| 問 1 時間の区切り | **(c) 両方**。行は季節。行の名前に「この世界の時計 (考古学ではこの細かさは分からない)」の札をつける。列に「層」をつける (層 = フェーズ。本物の時代の名前をそえ、【見立て】の札をつける) |
| 問 2 数と幅 | **(a)** 跡の本当の数 (割れた土器 1,489 個分など) + 考古学者の読み (「少なくとも」「いちばん多い・少し・ほとんど見つからない」) + 確かさ (高い・中くらい・低い)。**幅を出すのは人数の見積もりだけ** |
| 問 3 亡くなった人 | **(a)** 墓としてだけ出す。亡くなった日に、その人の家族の家が建っていれば**その家の床下**、なければ**村のまん中 (小屋のそば)**。世界の進み方は変えない。村を出て行った人の墓はない |
| 問 4 骨から分かること | **(b)** 本人の年齢の区分 + 骨の限りの注 (「55 の境目は骨では引けない (50 くらいより上)」「手伝える子と大人の境目は ±2〜3 年」「大人の男女は『たぶん』」「子の男女は骨の形では分からない」「死因は獣の歯のあとのほかは分からない」) + 札をつけた【今の調べ方】(歯の成分で「村の外で育った」、DNA で子の男女と母方の血縁。DNA が残らないこともある) |
| 問 5 使っている物 | **(a)** 入れない。跡は地面に入った物 (割れた・捨てた・埋めた物) と建物だけ。使っている土器・生きているヤギ・倉の中身は出さない |

技術の木の問い (`docs/tech_tree_design_draft.md` 6. 問 2):

| 問い | 決めたこと |
|---|---|
| 木をどこに見せるか | **(a)** ダッシュボードには跡が残る技術だけを考古学の証拠として出し、本物でいちばん早い年代と場所 (西アジア。土器は日本の大平山元 I も) を並べる。全部の木 (知っている・だれから・技能・創発と伝承) は、今のアプリの欄と `tech_tree_demo.html` に残す |

跡の作り方は、`archaeological_evidence.md` 6.1 の決まり R1〜R14 をそのまま使う (R12 の墓の場所は問 3 の答え)。

### 1.3 だから、こう見せる

本人がはじめに頼んだのは「個人のダッシュボード」と「社会のダッシュボード」で、あとから「家族」も見る単位になった。決めごとに合わせると、3 つの見方は次のようになる。

| 見方 | タブ | 文字の前 (いま) | G6 から |
|---|---|---|---|
| 社会 | **村** | 今この村を掘ったら何が残っているか (建物・土器のかけら・石の刃・骨・墓・人数の見積もり) | 加えて「記録」のタブに村の記録 |
| 家族 | **家** | 建物の跡 (建物 1〜12)。どの家族の家かは跡からは分からない | 家ごとの記録は「家の印」(印 A・印 B…) で見分ける |
| 個人 | **人** | 墓だけ (墓 1〜28)。生きている人は跡を残さない | 村の記録は家ごとで、人の名前は出てこない (今の G6 の作りでは) |

ほかに、層ごとにまとめて見る**層**のタブと、G6 の村の記録を見る**記録**のタブがある。タブは 5 つ。

どのタブも、いちばん上の「**この世界の時計**」で選んだ季節の終わりまでに地面に入ったものだけを見せる。季節を戻すと、その時に掘った村になる。

### 1.4 出さないもの

- 名前 (年の名の中のものだけは別。5.3 の D12)、人と家の番号、家族の名前
- 本当の人数、生きている人の年齢・男女の数、生きているヤギの数、使っている土器や鎌の数、倉の中身、食べた量、kcal、畑の数、豊かさの差 (記録の house_gini・wealth_gini)
- 正確な年齢・生まれた日・来た日・亡くなった日、獣に殺された (ザガ) のほかの死因、けが
- 掟・もめごと・まとめ役・投票・祭り・乳・話したこと・気持ち (これらは「跡に残らない」といういつも同じ 1 行で書くだけ。季節の行には書かない)
- G6 の「覚え」の幅 (覚えは記録ではない)、記録と本当の量のくらべ

`records/columns.json` の【調】の札は「あとで調べる人が知りうる」という広い意味なので、それで選ぶことはしない (人数・使っている土器・生きているヤギも【調】になっている)。ダッシュボードの数は、決まり R1〜R13 で跡を作ってから数える。

## 2. 画面

スマホ (幅 約 360 px、左右に 16 px のあき) を先に作り、PC (幅 1100 px 以上) は同じ部品を横に並べる。図の数は 28年の夏 (28年1〜30日目、3360〜3389 日目) を選んだとき。日本語は 1 字が 2 マスなので、図の右の線は少しずれる。

記号: ●●● 高い / ●●○ 中くらい / ●○○ 低い (確かさ。いつも字といっしょ)。【見立て】【仮定】【解釈】【議論あり】【未確認】【今の調べ方】【村】は札。

## 3. 部品ごとの中身

どの部品にも次のことが共通。
- 数のとなりに、考古学者の読み (今の言葉の 1 文) と確かさ (●●● 高い・●●○ 中くらい・●○○ 低い。字と印。色は使わない) をつける。印をさわると、その確かさの意味が出る
- 「**どう出したか**」をひらくと、元の記録 (やさしい言葉で)・決まり (R の番号)・計算 (本当の数を入れた式)・考古学者ならどう数えるか・確かさ、が出る。文は作るときに同じ数から作るので、数と文がずれない
- グラフにはかならず「**表で見る**」がある。吹き出しは見やすくするだけで、吹き出しにしかない数はない。キーボードで選んでも同じものが出る
- 選んだ季節 (この世界の時計) までの跡で数える

### K8 人数の見積もり (幅を出すのはここだけ)

- 問い: 何人くらい住んでいたか
- 計算 (R13。`archaeological_evidence.md` 4.7):
  - 床の広さ: 建った家の床の合計 ÷ 1 人 10 m² → 230 m² → 約 23 人 (小屋の床の広さは記録にないので入れない)
  - 建物の数: (建った家 + 小屋) × 1 軒 5 人 → 12 × 5 → 約 60 人
  - 村の広がり: 小屋と建った家を結んだ形 (凸包) の広さ × 1 ha あたり 120〜200 人 (西アジアの村の目安。`archaeological_evidence.md` では【未確認】なので、画面にも【未確認】をつける) → 6.2 ha → 約 750〜1,240 人。点が 3 つ (小屋 + 家 2 軒) より少ないと「見積もれない」。壁の土台は入れない
  - 幅 = いちばん少ない見積もり〜いちばん多い見積もり。何倍ちがうか = 多い ÷ 少ない (丸める前の数で)
  - 丸め方: 100 より小さい数はそのまま、100 以上は 10 の位で四捨五入 (746 → 750、1,243 → 1,240)
- 形: 10 倍ずつの目もり (10・100・1,000) に、床と建物は点、広がりは幅の棒。行ごとに方法の名前と式。色は青 1 色

## 4. 作り方

### 4.1 流れ

```
state.json (33.5 MB) ─┐
records/ (5.6 MB) ────┼─► tools/build_dashboard.py ─► 小さな JSON (60〜100 KB)
                      │      (読むだけ。同じ入力なら      │
                      │       同じ出力。時刻を入れない)   ├─► app/dashboard.html の中に埋める (いま)
                      │                                   └─► data/dashboard.json (走らせている実行を
                      │                                        止めたあと。本人がよいと言えば)
app/dashboard.html ◄── 自分の中の JSON か、相対パスの dashboard.json を読む (サーバーはいらない)
```

`app_data.json` (27.9 MB) や `state.json` はスマホには重く、artifact (1 ファイル 16 MB まで) にも Cloudflare (25 MiB まで) にものらない。だから、ダッシュボードは計算ずみの小さな JSON だけを読む。

### 4.2 `sim/society/tools/build_dashboard.py`

- Python の標準ライブラリだけ。入力は読むだけ
- 動かし方:
  ```
  py -3 -X utf8 sim/society/tools/build_dashboard.py --data <dataのフォルダ> [--embed sim/society/app/dashboard.html] [--out <json>] [--allow-data] [--check]
  ```
  - `--data`: `state.json` と `records/` のあるフォルダ。いまは写し (`.../scratchpad/dashboard/data`) を指す
  - `--embed`: html の `<!--DASH-DATA-->` と `<!--/DASH-DATA-->` のあいだの `<script type="application/json" id="dash-data">…</script>` だけを書きかえる。ファイルの改行の形はそのまま (newline='')。JSON の中の `</` は `<\/` にする
  - `--out`: JSON を別に書く。`sim/society/data/` の下は `--allow-data` がないと断る
  - `--check`: 作りなおして、埋めてある JSON と 1 バイトでもちがえば知らせる。下の確かめもする
- 読むときの決まり:
  - `records/meta.json` を読み、`state.json` を読む。`meta.state_day == state.day` と `meta.state_next_event == state.next_event` を確かめる。合わない、または `state.json` が書きかけで読めないときは、少し待って 3 回までやりなおし、だめなら止まる (0 でない終わり方)
  - 出力: キーを並べる、ensure_ascii=False、区切りは `(',', ':')`、改行は `\n`、時刻は入れない
- 計算の決まり:
  - 季節: `season_end(d) = d + 29 − d % 30`。489 日目までは F 層の行 (480〜489 日目は短い行)。季節の集まりの出来事 (前の季節の終わりの日の日付) は、記録と同じく次の行に入れる。毎日の出来事 (狩り・火) と季節の終わりの死はその日の季節の行
  - 層: `state.era_log` の G の日の次の日から
  - 建物: `state.camp` と `state.era2.homes` (x・y・start・built・sizes)。`households.home_start_day` と `home_built_day` と合うかを確かめる。広げた跡 = `sizes` の 2 つめ以降の日がその季節にあるとき
  - 食べ物をためた所: `season_household.home.built_day` ≤ 季節の終わり で、`store` のどれかが 0 より大きい最初の季節
  - 土器・刃: `season_village.pots_broken` / `sickles_broken` (null は null のまま。F 層の行は 0)
  - 炉: 出来事「火」で「おこした」あり「できなかった」なし
  - 骨: 出来事「狩り」(`data.killer` → ルク 1、文の「\((ピクの肉|魚) (\d+) 匹\)」)
  - ヤギ: `goats.count` > 0 の季節 (あるかないか)。ヤギの骨 = 帳簿のヤギ「つぶした」と出来事「ヤギを食べる」(年ごろ = (その日 − 生まれた日) // 120、雌雄は `snapshots.goats` から)
  - 家ネズミ: `pests` > 0
  - 祭り: `g5.feast.cost` に肉・魚・ピク・干し肉・ヤギがあるときだけ、骨のまとまり (肉 kg ÷ 0.2 = 何人分)。なければ何も出さない (「なかった」という印も出さない)
  - 墓: `people.json` の亡くなった人 (亡くなった日・人の番号の順に墓 1〜N。番号は増えるだけで変わらない)。亡くなった日の家族は `membership.json`、家が建っていたかは `households.home_built_day`
  - 植物: `stats[].eaten_by_kind` (K20)
  - 人数: K8
  - 年の名: `year_names.json`
  - G6: 4.6
- 確かめ (作るたびに。1 つでもだめなら止まる):
  1. もれ: 年の名の外のすべての文に、`people.json` の 73 人の名前・`households.json` の 20 の家の名前・`\b[PH]\d{2,3}\b`・「kcal」・「持ち主の印」がない。季節の文 (`seasons[].text`) と建物・墓・技の文に「祭り」「乳」がない
  2. 出してはいけないキー (4.4) がない
  3. 合計: 最後の行の `cum` = その季節までの `add` の合計 (かけら・刃・墓・家)。かけらの合計 = `pots_broken` の合計 = 作った − 今の数の増え
  4. 墓の数 = 亡くなった人の数、床下 + まん中 = 墓の数、どの墓の場所も決まる
  5. 祭りのあった季節となかった季節で、祭りから作った値がちがわない (肉のない祭りのとき)
  6. 大きさ: 150 KB をこえたら知らせ、300 KB をこえたら止まる
  7. 前に埋めた JSON とくらべて、古い季節の行の数が変わっていたら知らせる (記録を作りなおしたとき以外は変わらないはず)
  8. G6 に入ったら: 出来事から数えた印・封・記録の数が `season_village.g6` の数と合う
- 3389 日目の写しで作ったときに出るはずの数 (試しの表。写しのフォルダに置く): 建物 12 と小屋 1 / かけら 1,489・刃 339 / 墓 28 (床下 17・まん中 11) / 人数 23〜1,243 (丸める前) / 層の日数 F 490・G1 740・G2 300・G3 60・G4 120・G5 1,680

### 4.4 `sim/society/app/dashboard.html`

- 1 つのファイル。CSS と JS は中に書く。外から読むのは Google Fonts だけ (Dela Gothic One・Zen Kaku Gothic New・IBM Plex Mono)。グラフは自分で SVG を描く (ライブラリなし)
- 先頭に `<!doctype html>`・`<meta charset="utf-8">`・`<meta name="viewport" content="width=device-width, initial-scale=1">`。`<title>村の跡と記録</title>`
- データの読み方: `fetchAny(["dashboard.json", "../data/dashboard.json"])` (今のアプリと同じ相対パス、cache: no-store) を試し、埋めてある `#dash-data` とくらべて `built.state_day` の大きい方を使う。file:// で開いたときや artifact では埋めてある方になる
- つくり:
  - `<header>` (題・記録の日・1 年 120 日の注・リンク・明暗の切りかえ)
  - `<nav class="clock">` (K1。上に止まる)
  - `<nav class="tabs">` (K2)
  - `<main>` にタブごとの `<section>` (村・家・人・層・記録)
  - 下から出る紙 (`<dialog>`。PC では横の欄)

- 明暗: 色は `:root` の名前つきの値。暗い表示は `@media (prefers-color-scheme: dark)` の `:root:not([data-theme="light"])` と `:root[data-theme="dark"]` の 2 か所。`body` に地の色。明暗が変わったら (MutationObserver) グラフを描きなおす

### 4.6 G6 の記録の読み方

記録の `season_village.g6` は数の合計だけで、`snapshots` には G6 がなく、`era2.g6.records` は 8 季節分しか残らない。だから、季節ごとの中身は `state.json` の出来事から読む (形は `G6_design.md` 14.)。

| 出来事 | 読むもの | ダッシュボードでは |
|---|---|---|
| 印 | `data.household` (家の番号) | 最初に出た順に印 A・B… を決める。家の番号は外に出さない |
| 封 | 季節のまとめの文「{家}の印 N 回」「印のない封 N 回」 | 印ごとの封のかけらの数。家の名前 → 家の番号 → 印の文字に直してから出す |
| 記録 | 道具が開いた (`data.tool`)。季節の記録 (`data.count`・`data.how`・文の「{WHAT}（全部残せた|途中まで）。done / need 個分」。WHAT は 村の蓄えへの家ごとの出し入れ・ほかの村との交換と貸し借り・よその家の畑で刈った量) | はしご・記録がどこまで残ったか |
| 確かめる | 文の量 | 記録で確かめたこと |
| 交換・よその村・町 | 物と数・相手の村の向きと日数・町に届いた日 | 交換 (全部残ったときだけ)・町 |

- 家ごとの粘土の板 (蓄えが全部残った季節だけ): `season_household.village_flow` (入れた・出した、草の種にしてつかみ)・`fields.sown` (まいた) を 100 つかみで 1 個、働いた日 (`season_person.days_by_activity` の記録をつける・交換に行く・作る仕事) を 10 日で 1 個。家ごとの数は合計が記録の need と合うように大きい余りから配る。合わなければ「途中まで」にもどす
- 村の記録の文には人の名前 (記録をつけた人) が入るので、出来事の文はそのまま出さない
