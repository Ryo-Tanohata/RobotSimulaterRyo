## 2. 予定の木と、届いたかの決め方

### 2.1 予定の木 `sim/society/techtree/plan.json` (手で書く)

- `phases`: フェーズ 21 (F1〜F6・G1〜G15)。名前・部・本物の時代・文書
- `closures`: 本人の決めで閉じた G (今は G8: 104年120日目)。G1〜G7 は `era_log` (次のフェーズに入った日) から読む
- `nodes`: 技術 88。1 つごとに
  - `id`・`name`・`phase` (予定の G)・`kind` (仕事 / もの / やり方 / しくみ)・`prereq` (前提の技術の id)・`does` (できること)
  - `detect`: 届いたかを記録から見る決まり (下の 2.2)。`null` なら機械では見ない
  - `real`: 本物のいちばん早い年代 (`when`)・場所 (`where`)・出典 (`src`)・確かさ (`sure`: 文献 / 二次 / 記憶 / 議論あり / 未確認 / 見込み)
  - `gap`: 史実とのずれ (たたき台 4.3 のずれなど)
  - `code: false`: この世界にまだ仕組みがない (すり石・しっくい・布・水路・銅・回る台)。届かなくても村のせいではない
  - `heard`: よその便りの札の id。村がその話を聞いた日を「話だけ」として出す
- 材料: フェーズの表は `era2.py` (`ORDER2`・`NAMES2`・`SUBSTEPS`・`RETRO_SUBSTEPS`)、Society 1.0 は `phase.py`、計画は `docs/society2_phase_plan.md` と `docs/society2_extension_plan.md` (G7〜G14 の F と年代)。本物の年代は前の見本 (`tech_tree_demo.html`)・`docs/research/archaeological_evidence.md`・よその便りの札 (`hint_cards.json`)
- 【記憶】【二次】の年代は、そのフェーズの設計書を書くときに原典にあたって直す

### 2.2 届いたかの決まり (`detect`)

| 形 | 意味 | 例 |
|---|---|---|
| `{"ev": "種類"}` | その種類の出来事が初めて出た日 | `{"ev": "採集"}` |
| `{"ev": "種類", "text": "正規表現"}` | 文にその言葉をふくむ最初の出来事 (`not` はふくまないもの) | 狩り: `"text": "しとめた"` |
| `{"ev": "種類", "data": "鍵"}` | 出来事の `data` のその鍵が 0 でないもの | 土器: `"data": "count"` (焼き上げた) |
| `{"substep": "G6/F2"}` | G の中の区切り F に入った日 (出来事「区切り」か `era2.substeps`) | 印で封をする |
| `{"good": "言葉"}` | やりとり (`data.moves`・`data.thing`) に初めて出た物 | 赤い金属 |
| `{"law": "penalty"}` | その欄 (`penalty`・`tax`・`rate`) のある掟が初めて採用された日 | 罰のある掟 |
| `{"stall_done": "c2"}` | G7・G8 の物差しの条件がそろったか (日は記録にないので今日) | 取り立てを板に記して 2 年 |
| `{"day": N, "why": "…", "at": "F6"}` | 日を手で書いたもの (記録の仕組みの前のもの) | 作る人 (G3 の F3)・育てた植物で半分 |
| `{"any": [ … ]}` | どれかいちばん早いもの | 牛に犂 (G7 の F1 か G8 の F1) |

- **状態**: 届いた / 届かなかった (その G を閉じるまで起きなかった) / 予定 (まだ入っていない G)。今の G がまだ閉じていなければ「まだ」
- **早い・遅い**: 届いた出来事が、どの G のあいだに起きたか。フェーズに進んだ出来事 (「フェーズが G2 (…) に進んだ」など) の番号より後かで決める。だから、同じ日の区切り (季節の終わりに見て、次のフェーズに進む日) の出来事も分けられる。出来事のないもの (区切りの記録・手で書いた日) は、区切りの日を前のフェーズに入れる
- 例: 木の実を埋める (予定 F5) は 0年9日目にルオがした → 早い (F1)。土器 (予定 G3) は G4 に入った次の日に焼いた → 遅い (G4)

### 2.3 初めての記録 (機械で見つける)

出来事を 1 回だけ読んで (`archive.load_state` で、しまった年の出来事も戻して 約 100 万件)、新しい種類が初めて出た日を集める:

- 出来事の種類 (「年の名前」「崩れ」「倉から取る」など)
- やりとりに出た物 (交換・貸し借り・貢ぎの `moves` と `thing`。黒曜石・赤い金属の刃など)
- 記録の道具 (出来事「記録」の `tool`、「確かめる」の `how`)
- 決め方 (もめごとを収めた人 `by`、裁いた人、長老の言葉、貢ぎの答え、崩れのわけ)
- よその便りの札 (はじめて村に届いた日)
- 掟の中身: 言葉で分けた 28 の種類 (`build_tech_tree.py` の `LAW_TOPICS`) の、初めての案と初めての採用。言葉で結ぶので、まちがいがありうる【仮定】。ほかに、罰・取り立て・換算の欄のある掟

季節を進めるたびに作り直すので、新しい種類が出れば、ふえていく。全員が亡くなって戻してやり直したときは、記録といっしょに消える (その世界の歴史ではなくなるため)。

### 3.3 フェーズの区切りごとに足す手順 (Claude)

G を閉じたとき (評価の下書き `G?.md` を書くとき) に:

1. その G の文書 (`docs/society_phase/G?.md`・`G?_notes.md`・`part?.md`・`data/run_log.md`) と、ページの「初めての記録」の表 (その G の行) を読む
2. 候補ごとに、記録で確かめる: 出来事の番号 (`archive.load_state` で読んだ `state["events"][番号]`)・掟の番号 (`state["laws"]`)。仕組みを作る側が足したもの (お題の選び・つなぎ目・よその便り) かどうかも、コードと設計書で確かめ、`source` に書く
3. 予定の木の G にあり、予定どおりに開いたものは入れない (`checked_not_emerged` にわけを書く)

5. 予定の木に新しい技術が要るとき (たとえば G9 の設計で F が決まったとき) は `plan.json` の `nodes` を直す。G を本人の決めで閉じたときは `closures` に書く

### 4.1 季節ごとに自動で (2026-10-28 からつないだ)

`sim/society/tools/season_step.sh` (ワークフローが 1 季節ごとに呼ぶ) で、`step.py season` のあと、本物の村 (`sim/society/data`) のときだけ `build_tech_tree.py` を動かし、`app/tech_tree.html` もコミットに入れる。作れなくても季節とコミットは止めない (「技術の木: 作れなかった」と出るだけ)。試しの村 (`SOC_DATA_REL`) のときは動かさない。

**世界が変わらないことの確かめ** (2026-10-28): 本物の 12599 日目の data の写しを 2 つ作り、`step.py season` を、A は技術の木なし、B は技術の木ありで回した。季節のあとの `state.json` の sha256 は A・B・B の技術の木の前で同じ (`0057751e…`)。`data/` の下のファイルも A と B で 1 つもちがわなかった (`diff -rq`)。本物の data にはさわっていない (sha256 `fb5f77b8…` のまま)。技術の木は `step.py` が終わってから別のプロセスで読むだけなので、季節の結果には入らない。

## 5. 気をつけること・まだのこと

- 掟の中身の種類は言葉で分けた【仮定】。ほかの言葉の中に同じ字があると、まちがえる (「様子」の「子」など。なるべく長い言葉にした)
- 「届いた」は、その技術が初めて記録に出た日。広まった・止まった・忘れられた (たたき台の 3.1 の 5 つの状態) は、まだ出していない
- 本物の年代は、前の見本と調べの書き物から写した。【記憶】【二次】のものは原典で確かめていない
- G9 からの技術の `detect` は、まだ `null` (仕組みのコードがない)。G9 を作るとき、そのつなぎ目の出来事が決まったら書く
- たたき台の問い 2〜6 (ダッシュボードの考古学のページの木・広まりの決め方・持っている人と教わる・史実とのずれを直すか・お題に出す仕事) は、まだ決まっていない
