### 2.2 要素が届いたかの決まり (`detect`)

| 形 | 意味 | 例 |
|---|---|---|
| `{"ev": "種類"}` | その種類の出来事が初めて出た日 | `{"ev": "採集"}` |
| `{"ev": "種類", "text": "正規表現"}` | 文にその言葉をふくむ最初の出来事 (`not` はふくまないもの) | 狩り: `"text": "しとめた"` |
| `{"ev": "種類", "data": "鍵"}` | 出来事の `data` のその鍵が 0 でないもの | 土器: `"data": "count"` (焼き上げた) |
| `{"substep": "G6/F2"}` | G の中の区切り F に入った日 (出来事「区切り」か `era2.substeps`) | 印で封をする |
| `{"good": "言葉"}` | やりとり (`data.moves`・`data.thing`) に初めて出た物 | 赤い金属 |
| `{"law": "penalty"}` | その欄 (`penalty`・`tax`・`rate`) のある掟が初めて採用された日 | 罰のある掟 |
| `{"stall_done": "c2"}` | G7・G8 の物差しの条件がそろったか (日は記録にないので今日) | 取り立てを板に記して 2 年 |
| `{"day": N, "why": "…", "at": "F6"}` | 日を手で書いたもの (記録の仕組みの前のもの) | 作る人 (G3 の F3)・育てた植物で半分 |
| `{"any": [ … ]}` | どれかいちばん早いもの | 牛に犂 (G7 の F1 か G8 の F1) |

- **要素の状態**: 届いた / 届かなかった (その G を閉じるまで起きなかった) / 予定 (まだ入っていない G)。今の G がまだ閉じていなければ「まだ」
- **早い・遅い**: 届いた出来事が、どの G のあいだに起きたか。フェーズに進んだ出来事 (「フェーズが G2 (…) に進んだ」など) の番号より後かで決める。だから、同じ日の区切り (季節の終わりに見て、次のフェーズに進む日) の出来事も分けられる。出来事のないもの (区切りの記録・手で書いた日) は、区切りの日を前のフェーズに入れる
- 例: 木の実を埋める (予定 F5) は 0年9日目にルオがした → 早い (F1)。土器 (予定 G3) は G4 に入った次の日に焼いた → 遅い (G4)

### 2.3 初めての記録 (機械で見つける)

出来事を 1 回だけ読んで (`archive.load_state` で、しまった年の出来事も戻して 約 100 万件)、新しい種類が初めて出た日を集める:

- 出来事の種類 (「年の名前」「崩れ」「倉から取る」など)
- やりとりに出た物 (交換・貸し借り・貢ぎの `moves` と `thing`。黒曜石・赤い金属の刃など)
- 記録の道具 (出来事「記録」の `tool`、「確かめる」の `how`)
- 決め方 (もめごとを収めた人 `by`、裁いた人、長老の言葉、貢ぎの答え、崩れのわけ)
- よその便りの札 (はじめて村に届いた日)
- 掟の中身: 言葉で分けた 28 の種類 (`build_tech_tree.py` の `LAW_TOPICS`) の、初めての案と初めての採用。言葉で結ぶので、まちがいがありうる【仮定】。ほかに、罰・取り立て・換算の欄のある掟

季節を進めるたびに作り直すので、新しい種類が出れば、ふえていく。全員が亡くなって戻してやり直したときは、記録といっしょに消える (その世界の歴史ではなくなるため)。

## 3. 創発 `sim/society/techtree/emerged.json` (手で書く)

### 3.1 決め方

- **予定にない**: 予定の木にないこと (`node` は `null` か、近い技術)
- **予定より早い**: 予定の木では、もっと後の G のこと
- **予定と違う形**: 予定の木にあるが、ちがう形・ちがう使い方で起きた
- 1 つごとに: `id`・`day` (通しの日)・`name`・`kind`・`node` (関係する要素)・`tech` (`node` が `null` のときだけ。近い項目。その項目の「予定にない」として出る)・`source` (きっかけ: 村 / 場は作る側 / よその便り)・`what` (何が)・`history` (本物とくらべて)・`evidence` (出来事の番号)・`laws` (掟の番号)・`note`・`added` (いつ選んだか)
- `checked_not_emerged`: 確かめたが入れなかったもの (わけつき)。同じものを次に調べなおさないため
- 創発は、`node` の要素の入る項目 (か `tech`) に入り、その箱に ◆ の数が出る
- 機械で見つけた「早い」(予定の G より前に届いた要素) は、要素の一覧と箱に「▲ 早い」と出るので、手の一覧には、ふつうは入れない。手の一覧に入れるのは、わけや形まで読まないと分からないもの

### 4.1 季節ごとに自動で (2026-10-28 からつないだ)

`sim/society/tools/season_step.sh` (ワークフローが 1 季節ごとに呼ぶ) で、`step.py season` のあと、本物の村 (`sim/society/data`) のときだけ `build_tech_tree.py` を動かし、`app/tech_tree.html` もコミットに入れる。作れなくても季節とコミットは止めない (「テクノロジーツリー: 作れなかった」と出るだけ)。試しの村 (`SOC_DATA_REL`) のときは動かさない。

**世界が変わらないことの確かめ** (2026-10-28): 本物の 12599 日目の data の写しを 2 つ作り、`step.py season` を、A はテクノロジーツリーなし、B はテクノロジーツリーありで回した。季節のあとの `state.json` の sha256 は A・B・B のテクノロジーツリーの前で同じ (`0057751e…`)。`data/` の下のファイルも A と B で 1 つもちがわなかった (`diff -rq`)。本物の data にはさわっていない (sha256 `fb5f77b8…` のまま)。 2 本の木の形に作り直したあとにも、同じ確かめをもう一度して、同じ結果だった (2026-10-28)。テクノロジーツリーは `step.py` が終わってから別のプロセスで読むだけなので、季節の結果には入らない。
