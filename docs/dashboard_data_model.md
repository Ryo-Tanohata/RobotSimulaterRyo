# ダッシュボードのための記録の設計 (たたき台)

書いたのは Claude (2026-10-09)。本人「何を可視化するかを確かめたい。データベース設計だと思う」。
見せ方 (画面の並び・グラフの形) は、この表が決まってから相談する。

材料: `state.json`・`app_data.json`・季節の答え (`answers/dayNNNN/season/`)・`era2.py` を、15年29日目 (1769 日目) の時点で洗い出した。

## 0. 考え方

- **1 行 = 1 季節** を基本にする (この世界は 1 回 = 1 季節で進むので)。日ごとの細かい記録 (出来事 3.4 万件) は今のまま残し、表はそこから季節ごとにまとめる
- 見る単位は **人・家族・村・フェーズ** の 4 つ。家族を入れるのは、Society 2.0 では畑・ヤギ・家の倉・住まい・もめごとが家族ごとに決まるから
- 置き場所: サーバーがないので、本物のデータベースではなく **表の形のファイル** にする (アプリが読む JSON。Excel で開ける CSV も出せる)
- 記号: ○ もう記録にある / △ 今の記録から組み立てられる (過去の分も作れる) / × 記録にない (これから季節ごとに残す。過去の分は作れない)

## 3. 作り方 (案)

1. これから: 季節の終わりに、②〜⑤ の 1 行ずつを記録する (`era2.py` の季節の終わりの処理に足す。シミュレーションが止まっているときに入れる)
2. 過去の分: △ の列は、今の記録から組み立てる。× の列は過去の分は空にする
3. ダッシュボード用に、表をまとめた小さなファイル (数十 KB) を書き出す。今の `app_data.json` (14 MB) は、スマホでは重い

## 4. 気づいたこと (表の前に知っておくとよいこと)

- **代表でない大人の声がない**: 10年60日目からは、季節の集まりで答えるのは家族の代表だけ。タヒ・ウィロ・ケト・トワ・カイの気持ちと言葉は 10年30日目で止まっている。フウとアルは一度も答えていない
- **信頼 (trust) は使えない**: 食べ物を分けたときだけ変わる仕組みで、Society 2.0 では村の蓄えから自動で食べるので、止まっている
- **アプリに古いところがある**: 「5 人」「毎朝 7 時に 1 日分」などの文、フェーズの欄が Society 1.0 のまま、「生きている人」のグラフが大人だけを数えている (22 人なのに 15 人)、など。ダッシュボードを作るときに直す
