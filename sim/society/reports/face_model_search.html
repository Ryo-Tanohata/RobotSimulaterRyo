セナの顔さがし: こわくない顔のモデルと、作り方の調べもの

2026-11-22 の調べもの。ねらいは「ゲームのリメイク作品のような、アニメと写実の間の顔」 (体は人の比率、顔はととのっていて、目は少し大きく、鼻は小さく、肌はなめらか、目の陰影がきれい)。 特定のゲームの人物はまねしない。

1. いまの顔がこわい理由 (sena_mid_face.png を見て)

場所いまの様子こわく見える理由
目黒目が小さく、白目がほとんど見えない。黒い玉に光の点が 1 つだけ「穴」や「ガラス玉」に見え、生きた目に見えない
まぶた上まぶたの厚みと影がない。太い黒い線で囲っただけ目が顔に「はめこまれた部品」に見える
まつ毛・眉まつ毛がない。眉は前髪にかくれて、ひたいに細い線が 1 本表情が読めない。線がキズのように見える
口唇が厚くて平ら。上下の間が黒い 1 本線。歯が見えない口だけ少し笑い、目は笑っていない (ちぐはぐ)
肌オレンジ一色でテカテカ。ほおや鼻先の赤みがない粘土やプラスチックのように見える
形鼻は写実的で大きく、目は小さい。ほおが丸く子ども顔写実と記号がまざっていて、脳が「変だ」と感じる
髪板のような束。頭の丸みに沿っていないかつらをかぶった人形に見える

いちばん大きいのは 目 (白目・まぶた・まつ毛・目の影) と、写実と記号のまざり方。

かわりのモデルに必要なもの

  • 目が別の部品で、白目・虹彩 (黒目のまわりの色の輪)・ハイライト・まぶたの影がある
  • まつ毛と眉が形 (またはテクスチャ) で入っている
  • 口の中 (歯・舌) か、少なくとも口の中の色がある
  • 表情のための形の変化 (シェイプキー = 顔を動かす登録ずみの変形) がある: まばたき・あいうえお・笑い など
  • 鼻と口が小さく、目が少し大きい「ととのえた」比率
  • ライセンス (使ってよい条件) がはっきりしている

2. さがす条件

項目条件
ライセンスCC0 か CC-BY だけ。商用もよい。「AI に使うな」「再配布禁止」の文がないこと
形式.blend / .glb / .fbx / .vrm
形のつくり目・口のまわりが輪になった四角面 (動かしやすい)。表情のシェイプキーつき
部品目・歯・舌・まつ毛がある (なければ足す手間を書く)
頭だけか全身か頭だけなら MakeHuman の体に「つぎたす」。全身ならセナの体ごと入れかえも考える
面の数頭で 5 千〜3 万三角くらい (クラウドの CPU で描ける量)
テクスチャ1K〜2K。4K はメモリが重い
見た目アニメと写実の間。目が少し大きく、鼻が小さい
ここから取れるかこのクラウドは github.com・npm・PyPI だけ取れる (huggingface.co は見られるが、ファイル本体の配信先はふさがれていた)

4. プロフィールから顔を「作る」方法

(a) 数値で形を変える人物ジェネレーター (Blender)

名前見た目のはばコード / 作った人物のライセンスbpy 4.5 で画面なしに動くかプロフィール→数値
MPFB2 (MakeHuman)写実。アニメ寄りはないコード GPLv3 / 部品と出力は CC0 (「no limitation on what you can do with this combined output」)動く (いまセナで使用中)年齢・性別・体格・肌色が最初からある
CharMorph写実 (Antonia, Vitruvian など)コード GPL / Antonia CC-BY 3.0、Vitruvian CC0、MB 素体は AGPL一部。リグ作りに Rigify が要る体格・顔の形のつまみ
MB-Lab写実と アニメ素体ありコード GPL3 / データと出力は AGPL3。描いた絵 (2D) は自由Blender 4.0 以上。UI 前提の操作が多く、画面なしは要工夫年齢・体格・表情の組 (アニメ用表情もある)
Human Base Meshes写実の素体 (彫刻用)CC0読みこむだけなら可つまみはない
VRoid サンプル (CC0) + シェイプキーアニメ〜アニメ寄りCC0動く (今回試した)表情キー (joy, sorrow など) と骨の太さで調整

(b) 文字や絵から 3D を作る AI (GitHub)

名前顔の出来骨・表情ライセンス (原文の要点)GPU動かせる頭にできるか
TRELLIS / TRELLIS.2 (Microsoft)形はよいが、目・口は細部がつぶれるなし「MIT License」要 GPU (目安 16GB 以上。12GB は工夫が要る)大変。目・口の穴がなく、表情キーもない
Hunyuan3D-2 / 2.1 (Tencent)形・色ともに上手。顔は少しぼやけるなし「THIS LICENSE AGREEMENT DOES NOT APPLY IN THE EUROPEAN UNION, UNITED KINGDOM AND SOUTH KOREA」(地域限定の独自ライセンス)形だけなら 6GB 前後、色つきは 16GB 前後大変。形の下書きとしてだけ
TripoSR荒いなし「MIT License」CPU でも遅く動く×。顔には荒すぎる
InstantMesh中くらいなしコード「Apache License 2.0」(使う学習ずみ重みの条件は別に確認が要る)要 GPU大変
Stable Fast 3D中くらいなし「STABILITY AI COMMUNITY LICENSE」(年 100 万ドル未満なら商用可)要 GPU大変
CharacterGenアニメの全身。顔は小さく荒いA ポーズで出る「Apache License 2.0」要 GPU中。体は使えるが顔は描き直しが要る
StdGEN (CVPR 2025)アニメの全身。体・服・髪が分かれるなし (分かれているので付けやすい)「Apache License 2.0」。VRoid 由来のデータで学習要 GPU中。顔はやはり弱い
PanoHead写実の頭 (360 度)なし表示は CC-BY-4.0。学習データは公開できないと書いてある要 GPU×。メッシュでなく体積表現

まとめ: 今の AI 3D は、体や服の下書きには使えるが、顔には向かない。 目・まぶた・口の中が 1 つの面にくっついて出るので、まばたきも話す口もできない。

(c) 顔の統計モデル (3DMM)

名前ライセンス一言
FLAME (標準版)「non-commercial research」(研究だけ)商用不可
FLAME 2023 Open「CC-BY-4.0」(2025-11 公開)。色のモデルは別で BY-NC-SA (商用不可)形だけなら使える。写実
Basel Face Model (BFM)研究・非商用だけ使わない
DECA / EMOCA「License for non-commercial scientific research purposes」使わない
GNM Head (Google, 2026-07)「Apache License 2.0」。目・歯・舌・表情 383 種つきとても良い写実モデル。ただし重みの配信先 (HF の CDN) はここからふさがれていて試せなかった。写実なので、そのままでは「こわさ」は消えない

(d) 組み合わせの流れ (おすすめの考え方)

  • 写実の形をそのまま使うと、少しのずれで「こわく」なる。アニメ寄りの形 + 光の当たる素材 のほうが安全。
  • 流れの例: プロフィール → 2D の顔の絵 → VRoid 風の素体の数値を合わせる → 肌と目だけ写実寄りの素材にする。

(e) 形を変えなくても「こわさ」を減らす素材と光のコツ

  1. 虹彩を大きく (目の横幅の 45〜55%)。白目は真っ白でなく少しグレー・ピンク。
  2. 目にぬれた上ぬり (つやの膜) を 1 枚。ハイライトは 1〜2 個を絵として固定。
  3. 上まぶたの影 (目の上 1/3 を少し暗く) と、目頭・目じりの赤み。
  4. まつ毛は板 (カード) か太い線で。上まつ毛を濃く、下はうすく。
  5. 眉は前髪から少し出して、表情 (困り・笑い) に合わせて角度を変える。
  6. 肌は少しだけ光が中に入る素材 (SSS 0.1〜0.25)。ほお・鼻先・耳に赤み。テカりは弱く。
  7. 線はアニメのまま (目の線・まつ毛・眉は光の影響なし)、面は写実の光、という二本立て。
  8. 後ろからの光 (リムライト) で輪郭を出す。正面の光は柔らかく大きく。
  9. 口は閉じぎみ。唇の境は黒線でなく、少し暗い赤。
  10. 目と口の表情を必ずそろえる (口が笑うなら、目も下まぶたを少し上げる)。

5. プロフィール → 顔の数値の対応 (案)

プロフィール変える所
年齢子ども: 目を大きく・顔を丸く。大人: 顔を少し長く・あごを出す。年寄り: 目じりを下げ、しわはテクスチャで少しだけ
性別素体の選び分け (女性素体 / 男性素体)、眉の太さ、あごの幅
体格骨の太さ・長さ (VRM の人の骨)、ほおの肉 (シェイプキー)
気分・話し方ふだんの表情キーを 0.1〜0.3 だけ混ぜる (おだやか=joy 少し、きつい=angry 少し)、眉の角度
日焼け肌の色に色をかける (掛け算)。鼻・ほおを少し濃く
傷肌の上に傷の絵を重ねる (デカール)
両親父母の数値の平均 + 小さな乱数 (家族で似た顔になる)

6. おすすめ

上位 3 つ

  1. VRoid CC0 サンプル (千駄ヶ谷 篠 / Vivi / HairSample_Female) — CC0、github から取れる、目・まつ毛・眉・口・表情キーがそろう。3 万三角ほどで CPU でも軽い。今回の試し描きで「こわさ」がないことを確認。
  2. MB-Lab のアニメ素体 — 数値で年齢・体格を変えられる。ただし出力は AGPL (この repo は公開なので問題は小さいが、条件外)。
  3. FLAME 2023 Open / GNM Head — 写実の形の「数値化」用。そのままは使わず、プロフィール→数値の研究用に。

クラウド (CPU だけ・bpy・github だけ) でのおすすめの流れ

  1. VRoid CC0 素体を github から取る (1 体 15〜18MB)。
  2. glTF として読みこむ (今回これで動いた)。表情キーも入る。必要なら VRM 用アドオン (github.com/saturday06/VRM-Addon-for-Blender) を足す。
  3. プロフィールから数値を作る (上の表)。表情キーと骨の太さ、肌の色、傷の絵を当てる。
  4. 素材を「線はアニメ・面は写実の光」にかえる (今回の試しスクリプトのやり方)。
  5. 体: まずは 全身を VRoid 素体に入れかえ がいちばん楽で、顔と体の画風がそろう。MakeHuman の体を残すなら、頭と首から上をつぎたし、首の境を髪とえりでかくす (手間は中)。
  6. 村の服は今の服をそのまま流用できないので、VRoid 素体用に作り直すか、簡単な服を足す。

本人の PC (RTX 5070) でのおすすめの流れ

  1. プロフィールを文章にする (年齢・体格・日焼け・気分など)。
  2. 2D の顔の絵を作る (商用可の画像モデルを選ぶ。例: SDXL 系。FLUX.1-dev は非商用なので注意)。
  3. その絵を見ながら VRoid Studio で顔を作る (本人がもう使っている道具。いちばん確実)。
  4. VRM で書き出して、クラウドへ (github 経由など)。あとはクラウドの手順 3〜6。
  5. 体や服の下書きがほしいときだけ、StdGEN / CharacterGen (Apache-2.0) や TRELLIS.2 (MIT) を使う。顔には使わない。
